# 情侣关系养成与 AI 应用产品讨论稿

## 一、产品方向

目标是打造一款面向情侣、尤其是异地情侣的关系维护 App。产品不是单纯的聊天工具，也不是单纯的恋爱游戏，而是让两个人通过聊天、DeepTalk、每日任务和共同养成，持续经营一个只属于他们的虚拟空间。

核心表达可以概括为：

> 两个人的真实互动，会持续改变一个只属于他们的共同世界。

产品的外层是轻量的宠物养成和空间装扮，内层是情绪表达、深度沟通、共同计划和关系记忆。

## 二、市场情况

现有产品大致分为几类：

| 类型 | 代表产品 | 主要功能 | 可以借鉴的地方 |
|---|---|---|---|
| 私密情侣空间 | [Between](https://apps.apple.com/ca/app/between-couples-love-tracker/id458035189) | 私聊、相册、语音、日历、纪念日、倒计时 | “只属于两个人”的空间心智清晰 |
| 中国本土综合型情侣 App | [小恩爱](https://apps.apple.com/cn/app/%E5%B0%8F%E6%81%A9%E7%88%B1-%E6%83%85%E4%BE%A3%E5%BF%85%E5%A4%87%E6%81%8B%E7%88%B1%E8%AE%B0%E5%BD%95%E8%BD%AF%E4%BB%B6/id524690790)、[微爱](https://www.welove-inc.com/about) | 聊天、相册、日记、纪念日、虚拟小家、农场、打卡、游戏 | 本土化、情侣共同经营、功能丰富 |
| 关系沟通训练 | [Paired](https://support.paired.com/en/articles/164632-what-is-paired) | 每日问题、伴侣测验、练习、主题包、游戏、关系洞察 | 内容结构清晰，强调每天几分钟的连接 |
| 异步深度提问 | [Agapé](https://apps.apple.com/us/app/agap%C3%A9-feel-close-when-apart/id1507907556) | 个性化每日问题、双方回答后互相解锁、异地主题 | 适合异步关系，减少同时在线要求 |
| 问题、约会和建议 | [Lovewick](https://lovewick.com/) | 问题库、约会创意、研究型建议、日记、愿望清单 | 把内容和现实行动连接起来 |
| 爱的表达和习惯 | [Love Nudge](https://apps.apple.com/us/app/love-nudge/id495326842) | 爱的语言、提醒、表达目标、互动 nudges | 把“理解对方”转化为具体行动 |
| 情侣共同生活管理 | [Cupla](https://www.cupla.app/the-app/) | 共享日历、待办、约会规划、关键日期、愿望清单、AI 助手 | 解决时间安排和共同生活的精神负担 |

从这些产品可以看出，市场主要有三条路线：

1. 私密聊天和恋爱记录。
2. 问题卡片和关系成长。
3. 日程、任务和共同生活管理。

初步的机会点不是再做一个聊天窗口，也不是堆更多小游戏，而是把异地场景、深度沟通、情绪安全和共同养成连成一条低压力的闭环。

## 三、主要用户痛点

以下内容属于需要通过用户访谈和测试继续验证的假设：

- 有话想说，但不知道怎样自然开始。
- 聊天很多，却一直停留在“吃了吗、在干嘛”这类浅层内容。
- 两个人的作息和时区不同，很难同时在线。
- 一谈敏感话题就容易因为语气、延迟回复或误解而升级冲突。
- 不能一起吃饭、散步、看电影，异地关系缺少共同生活感。
- 想表达关心，却不清楚对方现在需要倾听、建议、安慰还是空间。
- 重要的小事埋在聊天记录里，容易忘记。
- 关系维护本身可能变成打卡压力。
- 一方很积极，另一方较少使用时，产品容易变成单方面任务。
- 用户希望亲密，但也担心定位、已读、数据使用和隐私泄露。

## 四、产品核心定位

建议将产品定位为：

> 一款让异地情侣通过共同养成、深度对话和 AI 陪伴，持续经营一个只属于两个人的小世界。

第一核心用户可以收窄为：已经确定关系、异地至少一个月、年龄约 20～35 岁、愿意主动维护关系的情侣。

第一核心目标不是让用户每天停留很久，而是让他们每周完成 2～3 次有回应的互动，并且觉得彼此更了解了。

## 五、游戏化设计

### 1. 核心循环

建议的基础循环是：

```text
进入 App
→ 看到宠物和共同空间
→ 选择一个轻任务或深度任务
→ 两个人完成互动
→ 获得资源
→ 装扮宠物和空间
→ 形成共同记忆
→ 解锁新的互动内容
```

### 2. 任务分层

- 30 秒任务：发送一张照片、告诉对方今天的心情、送一个小礼物。
- 3 分钟任务：回答轻问题、说一件感谢对方的事、分享一个最近的烦恼。
- 10～20 分钟任务：完成一次 DeepTalk、一起看一段内容、讨论未来问题。
- 现实任务：约定一次视频通话、规划下次见面、完成共同愿望。
- 惊喜任务：写一封延迟解锁的信、准备一段语音或照片彩蛋。

### 3. 资源经济

可以设计一个主要软货币，例如“星星”“心意”或“能量”，再搭配：

- 宠物皮肤；
- 房间家具；
- 主题背景；
- 宠物动作；
- 氛围特效；
- 互动动画；
- 主题任务包；
- 共同空间装饰。

资源来源可以包括：

- 完成每日轻任务；
- 双方完成一次 DeepTalk；
- 共同保存一段回忆；
- 完成一次现实约会或共同任务；
- 完成阶段性关系主题；
- 参加限时活动；
- 观看主动选择的奖励广告。

不建议把以下行为直接量化奖励：

- 回复速度；
- 谁更主动；
- 分享了多少隐私；
- 负面情绪的严重程度；
- 连续登录天数。

否则容易把关系变成比较和考核。

### 4. 游戏化原则

- 合作，不竞争。展示“你们共同建成了什么”，不要展示谁完成得更多。
- 奖励连接，不奖励暴露。用户不应为了奖励被迫透露隐私。
- 允许缺席。提供暂停、跳过、补做和低能量模式。
- 宠物不惩罚用户。不要让宠物因为几天不登录就生病、饥饿或哭泣。
- 游戏层应该服务于关系，而不是让关系服务于游戏数值。

## 六、AI 的定位

AI 不应该被设计成一个替代伴侣的聊天机器人，也不应该负责自由生成所有游戏内容。

更适合的定位是：

1. 关系互动的内容策划者。
2. 情侣共同空间的场景导演。
3. 已有资产和任务的个性化匹配器。
4. 可选的表达和约会助手。

### 1. AI 自动布置

AI 不生产新的宠物、家具、皮肤或动画，而是从用户已经解锁的资产中选择并组合。

例如，AI 可以输出一份场景配置：

```json
{
  "background": "room_night_03",
  "pet_skin": "cat_pajama_01",
  "pet_animation": "sleepy_02",
  "furniture": ["sofa_01", "lamp_02"],
  "effects": ["star_particle_01"]
}
```

Unity 客户端根据资产 ID 加载已有资源并渲染。AI 没有权限：

- 使用未解锁资产；
- 修改资源数量；
- 解锁新物品；
- 修改会员状态；
- 删除用户布置；
- 生成任意代码或文件。

### 2. AI 的工作流程

```text
用户状态和互动信号
→ AI 选择场景配置
→ 服务端检查资产权限
→ 规则系统校验兼容性
→ Unity 加载场景
→ 用户确认、保存或撤销
```

AI 可以负责“选什么、怎么搭配”，规则系统负责“能不能放”。

需要设置的硬规则包括：

- 只能使用已解锁资产；
- 一个家具槽只能放指定类型的家具；
- 背景、墙纸和家具必须兼容；
- 同类装饰不能超过数量上限；
- 文字区域必须保持可读；
- 用户锁定的物品不能被替换；
- 自动布置必须可以撤销；
- 每次布置应保存为可恢复的场景快照。

### 3. AI 使用的状态信号

不建议默认读取所有私人聊天内容来判断情侣状态。可以优先使用：

- 用户主动选择的心情；
- 最近完成的互动类型；
- 最近使用的主题；
- 是否完成了 DeepTalk；
- 最近一次共同任务的类别；
- 时间、季节和纪念日；
- 双方选择的陪伴需求。

例如：双方都选择“低能量”，最近主题是“互相感谢”，当前时间是晚上。AI 可以布置成安静、温暖、低刺激的房间，给宠物换上睡衣并播放休息动画，但不应据此判断“你们的关系出了问题”。

### 4. AI 其他可做的事情

- 从已有问题库中推荐当前合适的话题；
- 避免重复问题；
- 根据双方状态调整问题难度；
- 从任务模板中组合新的任务卡；
- 为 DeepTalk 生成自然追问；
- 帮用户把语气改得更温和；
- 根据共同愿望推荐约会计划；
- 把聊天内容整理成待确认的共同记忆；
- 提供冲突讨论的结构化流程；
- 为异地情侣提供时区和时间安排建议；
- 提供翻译和跨语言表达辅助。

### 5. AI 不应该做的事情

- 给情侣打感情分数；
- 判断谁更爱谁；
- 推断出轨或分手倾向；
- 自动暴露另一方的私密回答；
- 代替用户发送强情绪消息；
- 用宠物制造恐惧和内疚；
- 把自己包装成心理治疗师；
- 默认使用私人聊天训练模型。

共同记忆建议使用：

```text
AI 提取候选内容
→ 用户预览和修改
→ 双方确认
→ 进入共同空间
```

## 七、会员和广告

基础的关系体验应当保持可用：

- 基础宠物；
- 基础任务；
- 每日轻互动；
- 一定数量的 DeepTalk；
- 基础房间和记忆功能。

会员可以提供：

- 更多宠物、皮肤和空间；
- 高级主题包；
- 更强的 AI 个性化；
- AI 语气辅助和约会规划；
- 更大的记忆空间；
- 跨语言翻译；
- 高级季节活动；
- 去除广告。

广告建议只使用用户主动观看的奖励广告，放在商店、资源领取或装饰解锁位置。不要在私聊、DeepTalk、冲突修复和情绪低落时插入广告。

会员最好按“情侣关系”购买，一方购买后双方共享权益，降低一方付费、另一方无法使用的摩擦。

## 八、Unity 还是 Android 原生

如果产品核心包含共享宠物、空间布置、动画、皮肤、资源掉落和小游戏，建议优先使用 Unity。

Android Studio 本身只是开发工具，真正的对比是 Unity 与 Android 原生开发（Kotlin + Jetpack Compose）。

| 维度 | Unity | Android 原生 |
|---|---|---|
| 宠物、动画、场景 | 强 | 需要大量自建方案 |
| 资产和皮肤管理 | 强 | 较繁琐 |
| Android 与 iOS 复用 | 较好 | 需要分别开发 |
| 聊天和输入体验 | 需要额外处理 | 更自然 |
| 推送、支付、权限 | 需要插件和原生桥接 | 更方便 |
| 系统小组件和后台任务 | 较麻烦 | 更方便 |
| 游戏化视觉表现 | 强 | 需要额外搭建 |
| 包体和启动速度 | 通常更重 | 通常更轻 |

建议采用 Unity 作为主要客户端，但不要把所有业务都交给客户端。

### Unity 负责

- 宠物；
- 共同空间；
- 家具和皮肤；
- 动画和特效；
- 资源掉落表现；
- 小游戏；
- AI 自动布置后的场景渲染。

### 后端负责

- 用户和情侣绑定；
- 聊天和 DeepTalk；
- 任务状态；
- 资源数量；
- 资产解锁；
- 会员权益；
- 广告奖励；
- AI 调用；
- 推送和数据同步。

资源和解锁状态必须由服务端校验，不能让 Unity 客户端直接决定，否则容易被修改本地数据刷资源。

## 九、建议的开发阶段

### 第一阶段：垂直原型

用 Unity 快速验证核心玩法：

- 一只宠物；
- 一个房间；
- 5～10 件家具；
- 3 套预制主题；
- 几个简单任务；
- 完成任务获得资源；
- AI 从已拥有资产中自动布置房间。

这一阶段重点观察：

- 情侣是否愿意一起养成；
- 任务是否有趣；
- 资源奖励是否有吸引力；
- AI 布置是否比手动布置更方便；
- 用户是否觉得轻松，而不是有压力。

### 第二阶段：关系功能

- 情侣绑定；
- DeepTalk；
- 任务同步；
- 资源服务端校验；
- 共同记忆；
- 通知；
- 会员和奖励广告；
- AI 个性化推荐。

### 第三阶段：扩展体验

- 更多房间和宠物；
- 多种小游戏；
- 语音功能；
- 小组件；
- 节日活动；
- 更复杂的共同愿望和约会规划。

## 十、第一版建议暂时不做的内容

- 公开情侣社区；
- 复杂的虚拟农场；
- 位置监控；
- 关系排行榜；
- 感情评分；
- 自动诊断；
- 大量连续签到；
- AI 自由生成游戏资产；
- 让宠物因用户不登录而受到惩罚。

## 十一、待验证的问题

开发前需要通过访谈、问卷和小规模原型验证：

1. 用户最想解决的是没话说、没时间，还是容易误解？
2. 他们更愿意每天使用 3 分钟，还是每周使用一次 20～30 分钟？
3. 双方回答后互相解锁，是有趣还是麻烦？
4. 哪些任务能引起后续对话，而不是完成后立即结束？
5. 宠物养成对情侣来说是长期动力，还是只在最初有吸引力？
6. 用户是否愿意让 AI 使用聊天摘要和互动记录？
7. 一方积极、一方低频使用时，产品能否继续成立？
8. 用户更喜欢温馨小家、奇幻冒险，还是现实生活模拟？
9. AI 应该像隐藏在后台的系统，还是有明确人格的宠物伙伴？
10. 核心体验应该偏向每日轻互动，还是每周深度对话？

## 十二、当前建议

第一版建议确定为“轻养成 + 深聊天 + AI 自动布置”：

- 用 Unity 承载宠物、空间和游戏化视觉；
- 用后端管理关系、任务、资源和会员；
- 用预制资产库保证内容质量和经济系统可控；
- 用 AI 做状态理解、资产搭配、任务推荐和表达辅助；
- 不让 AI 自由生成核心游戏资源；
- 不让游戏系统制造关系焦虑；
- 先用一个宠物、一个房间和少量资产验证核心循环。
