# 关系状态与签到

## 目标

不用写长消息，也能让伴侣知道我现在需要什么。

## 状态

| 状态 | 默认回应 |
|---|---|
| 想被听见 | 我在，慢慢说 |
| 想要抱抱 | 发送拥抱 |
| 想要建议 | 要不要一起想办法 |
| 想安静一下 | 好的，我在这里 |
| 想分享 | 发起轻量分享 |
| 今天能量低 | 提供 30 秒回应 |

状态生成关系线索，可设置有效期、是否提醒和是否保存历史。允许撤回和修改，过期后归档。不转成情绪分数，不显示等待时间和积极度。

状态发布时区分“需要回应”和“状态播报”。前者必须由伴侣真人回应；后者可以在用户同意后由 AI 宠物询问一次，再把真人回答交给伴侣查看。

## 双层状态模型

状态由 回应需求和当前状态组成。回应需求决定伴侣下一步可以做什么；当前状态帮助伴侣理解背景。

### 回应需求

- 想被听见；
- 想要抱抱；
- 想被陪着；
- 想要建议；
- 想安静一下；
- 想一起庆祝；
- 想重新开始聊；
- 想让对方先主动；
- 想暂时保持联系；
- 不知道怎么说，但想被发现。

### 当前状态

- 今天能量低；
- 有点烦；
- 有点委屈；
- 心里有点乱；
- 有点孤单；
- 很想你；
- 最近很开心；
- 有件事想分享；
- 正在忙；
- 不太想说话；
- 想转移一下注意力；
- 今天需要一点鼓励。

用户可以各选一项，例如想被陪着 + 心里有点乱。

## 自定义状态

首版允许用户在固定状态之外补充自由文字，也可以收藏常用表达。固定状态负责系统行为，自由文字负责具体表达。

自定义文字不会直接改变 AI 介入、提醒和有效期。系统如需将其归类为需求型或播报型，必须向用户展示归类结果并允许修改。
