# Figma 原型设计方案 v0.1

## 原型目标

验证第一版核心闭环是否比普通聊天更容易促成一次真实互动：

状态表达 → 关系线索 → 真人回应或 AI 开口 → 类型化会话 → 互动记录 → 可选共同记忆。

本轮原型不追求覆盖所有页面，优先验证页面结构、会话类型和三条关键路径。

## 视觉方向

- 移动端画板：390 × 844；
- 温暖、私密、低压力；
- 以奶油白为底，珊瑚、薰衣草紫、薄荷绿作为状态和事件区分色；
- 大圆角卡片、柔和阴影、少量宠物和房间插画；
- 信息重点放在“现在可以做什么”，不模仿社交软件的消息流；
- 关系动作使用明确文字和图标，不只依赖 Emoji；
- 重要状态用色彩、标签和文案共同表达，不能只靠颜色。

## 页面清单

### 1. Today / 今日关系脉搏

首页展示：

- 顶部情侣头像和共同空间入口；
- 今日关系脉搏；
- 当前状态；
- 待回应事件；
- 轻触回应；
- 今日主题；
- 共同记忆入口；
- 宠物和房间的轻量变化。

首页不展示完整聊天消息流。

### 2. Inbox / 关系收件箱

会话类型列表：

- 普通聊天；
- 每日主题；
- 对方事件；
- 对方状态；
- 对方日记；
- AI 宠物助手；
- 共同任务。

每个列表项显示类型、摘要、下一步、有效期和状态。主列表只保留活跃、待回应和固定内容，已完成内容进入归档。

### 3. State Composer / 发布状态

结构：

- 一个回应需求；
- 一个当前状态；
- 可选补充文字；
- 是否允许 AI 宠物询问；
- 默认有效期；
- 可见范围；
- 发布按钮。

需求型状态和播报型状态必须在页面上有清晰说明。

### 4. State Event / 状态事件

伴侣侧看到：

- TA 的状态；
- 补充文字；
- 推荐回应；
- 六个关系动作中的主动作；
- 暂时不方便；
- 进入主题会话。

需求型状态显示真人回应入口，不显示 AI 自动回复。

### 5. AI Prompt / 宠物询问

播报型状态的 AI 只提出一句具体开放问题：

“今天最让你累的部分是什么？”

页面明确显示：

- 这是宠物在代为开口；
- 用户的回答会默认生成伴侣可见事件；
- 可以隐藏原文；
- 可以跳过。

### 6. Topic Session / 主题会话

顶部固定显示：

- 会话类型；
- 原始状态或事件；
- 双方参与状态；
- 完成条件；
- 可见范围。

底部不是普通聊天输入框，而是主题回答区。完成后提供：

- 继续聊；
- 发送关系动作；
- 保存为共同记忆；
- 结束并归档。

### 7. Event Card / 塔罗或抽签事件

流程：

发起“帮我摇一摇” → 对方打开事件 → 摇一摇或点击抽取 → 展示结果 → AI 给出模糊、开放式解读 → 对方回应 → 继续聊。

解读不输出确定结论、预测或决策命令，只提供：

- 轻量象征解释；
- 一个可讨论的问题；
- 一个现实选择入口。

### 8. Interaction Timeline / 互动记录

两个页签：

- 互动记录；
- 共同记忆。

互动记录自动收集塔罗、主题、状态回应、日记授权和关系动作等事件，并可点击回到原窗口。普通聊天和纯游戏过程不逐条进入时间线。

### 9. Shared Space / 共同空间

展示宠物、房间和最近一次互动带来的变化。空间不显示情侣等级和关系评分，只展示共同完成的结果。

## 关键原型路径

### 路径 A：需求型状态

今日关系脉搏 → 发布“想被陪着 + 心里有点乱” → 对方状态事件 → 发送拥抱 → 进入主题会话 → 真人文字回应 → 互动记录 → 可选保存共同记忆。

### 路径 B：播报型状态

发布“今天能量低” → 允许宠物询问 → 宠物问一个开放问题 → 用户回答 → 伴侣收到可见事件 → 进入主题会话 → 伴侣真人回应。

### 路径 C：塔罗／抽签

发起塔罗事件 → 伴侣帮助摇一摇 → 展示结果和模糊解读 → 生成讨论问题 → 选择继续聊 → 创建独立主题会话 → 结束后可保存记忆。

## 组件状态

每个核心组件至少设计：

- normal；
- pressed；
- loading；
- waiting；
- success；
- expired；
- muted；
- offline；
- deleted；
- permission denied。

## 原型验收问题

- 用户是否理解普通聊天和主题会话的区别；
- 用户是否知道自己当前需要对方做什么；
- AI 是否被理解为宠物助手，而不是伴侣替代品；
- 塔罗结果是否自然地进入双方对话；
- 互动记录是否能让用户快速找回当时的窗口；
- 页面是否在 5 秒内给出明确下一步；
- 通知和未回应状态是否没有制造压力。

## 暂不放入本轮 Figma

- 复杂小游戏合集；
- 完整会员和商店；
- 多宠物、多房间；
- 自定义关系动作；
- 公开社区；
- 大量设置页；
- 真实支付、推送和传感器实现。
